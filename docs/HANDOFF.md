확정되지 않은 사항은 **[확인 필요]**로 표시한다. 사용자가 말하지 않은 사실은 지어내지 않는다.

## 1. 확정된 것

| 항목 | 결정 |
|---|---|
| 사이트 제목 | **THEREFORE · 그러므로** |
| 부제 | **인생은 초등학교에서 배운 것의 복습이란다.** (마침표 포함) |
| 글의 성격 | 교육론, AI 활용, 그 밖의 '생각'. 장소·여행이 아니라 글 중심 |
| 글쓴이 | 사용자 혼자 |
| 제작 방식 | Git + MDX (ELSEWHERE 방식). DB·로그인·편집 화면 없음 |
| 저장소 | `burntbread-jpg/therefore`, 공개(2026-11-19 생성). 그전 작업은 Google Drive `THEREFORE` 폴더에도 백업해 두었다 |
| 글 구성 | **시리즈(연재) 중심**. 세부 분류는 나중에 다듬는다 |
| 기획 문서 위치 | 저장소 문서(README, 이 파일) |

### 제목을 THEREFORE로 고른 이유

- 자매 사이트와 글자로 이어진다: `elsewHERE · HERE · tHEREfore`.
- '그러므로'는 생각 끝에 나오는 말이라 생각을 올리는 사이트의 성격과 맞는다.
- 부제와 붙이면 문장이 된다: "그러므로, 인생은 초등학교에서 배운 것의 복습이란다."
- 약점: 복습의 감각은 이름보다 부제가 맡는다. 흔한 영어 단어라 이름만으로 검색되기 어렵다. 같은 이름의 서비스·도메인 여부는 **[확인 필요]**.

### 경과

AGAIN(첫 추천) → THEREFORE(자매 사이트와 연계 강화) → AGAIN → **THEREFORE(최종)**.
AGAIN은 '복습'과 뜻이 가장 잘 맞지만, 사용자는 결국 자매 사이트와 글자로 이어지는 쪽을 골랐다.

검토했지만 고르지 않은 제목: AGAIN · 다시 / ANEW · 새로 / REVIEW · 복습 / RECESS · 쉬는 시간 / NOTEBOOK · 공책 / WHY · 왜 / HERE AGAIN · 다시, 여기 / ELSEWHEN · 다른 때.

## 3. 자매 사이트와의 연계

- 로고: 세 사이트 모두 영문 대문자 한 단어 + 한글 보조 제목 문법을 따른다.
- 아래쪽(footer)에 세 사이트를 같은 형식으로 나란히 적는 가족 표기를 둔다. 예: `ELSEWHERE · HERE · THEREFORE`.
- 디자인 기준은 ELSEWHERE `docs/DESIGN_SYSTEM.md`의 에디토리얼 문법을 출발점으로 한다: 가는 선, 명조 제목, 표 형식 숫자, 인덱스 번호(01, 02).
- HERE에서 얻은 교훈: 굵은 글자, 그림자, 알약 모양 버튼은 "감도가 떨어진다"는 평을 들었다. 처음부터 쓰지 않는다.
- 바탕색·제목 글꼴을 ELSEWHERE(Paper #F6F3ED, Noto Serif KR)와 같게 할지, HERE처럼 따로 둘지는 홈 시안 단계에서 고른다. **[확인 필요]**

## 4. 정보 구조

### 결정: 시리즈(연재) 중심

사용자: "시리즈 물로 가자." 글은 주로 시리즈 단위로 묶어 올린다. 세부 분류(주제·형식)는 나중에 다듬는다.

시리즈 중심일 때의 제안(확정 아님):
- 홈 첫 화면의 주인공은 시리즈 목록이다. 시리즈마다 제목, 한 줄 소개, 편수, 최근 회차.
- 글 제목 옆에 `시리즈명 · 3편`처럼 회차를 표시한다.
- 시리즈 페이지는 목차처럼 회차 순서대로 보여 준다(01, 02, 03…).
- 글 끝에 '이전 편 / 다음 편'.
- 시리즈에 속하지 않는 짧은 글을 둘지: **[확인 필요]**
- 첫 시리즈 목록(이름, 다룰 내용): **[확인 필요]**

### 분류 체계 후보 (이전 논의. 시리즈 아래 보조 분류로 쓸 수 있음)

| 안 | 분류 | 장점 | 단점 |
|---|---|---|---|
| A. 주제 | 교육론 / AI 활용 / 생각 노트 (1음절로 줄이는 변형 가능) | 처음 온 독자가 바로 이해. 검색·공유에 유리 | 밋밋함. 두 주제에 걸친 글이 애매 |
| B. 교과목 | 국어·수학·바른생활·슬기로운 생활… | 부제 컨셉과 가장 잘 맞고 기억에 남음 | 억지 대응이 생김(AI 활용은 무슨 과목?). 독자가 과목 이름을 해석해야 함 |
| C. 형식 + 주제 태그 | 긴 글 / 짧은 메모 / 연재 / 밑줄(인용) | 쓰는 리듬과 맞고 짧은 메모를 부담 없이 올림 | 주제로 찾아 읽기 약함. 태그 관리 필요 |

지금까지의 추천: A의 주제 분류에 C의 형식 표시(긴 글·메모)를 더하고, 초등학교 감각은 분류 이름이 아니라 화면 표현(예: '1교시' 번호, 시간표 같은 목록)으로만 쓴다.

### 주소 설계 후보

분류와 관계없이 글 주소를 고정해 두면 분류를 나중에 바꿔도 링크가 깨지지 않는다. 그래서 분류 결정을 미뤄도 이 부분은 먼저 정해 둘 수 있다.

| 주소 | 내용 |
|---|---|
| `/` | 홈 |
| `/series` | 시리즈 전체 목록 |
| `/series/[series]` | 시리즈 목차 |
| `/notes/[slug]` | 모든 글. 시리즈를 옮기거나 이름을 바꿔도 링크가 깨지지 않도록 시리즈와 분리 |
| `/topics/[topic]` | 분류별 목록 (분류 확정 후) |

## 4-1. 3D: 원고지는 고정, 글 목록을 3D로

- 사용자 정정: 3D로 움직일 것은 원고지가 아니라 **글이 게시판처럼 누적되어 올라가는 부분**이다. 원고지(부제)는 2D로 고정.
  - 원고지가 3D로 모이는 시안(`drafts/c-3d.html`, `manuscript3d.js`)은 쓰지 않는다. 기록으로만 남긴다.
- 사용자 요청: 최대한 창의적이고 정교하게.
- 시안 D **나선형 교육과정**(`drafts/d-spiral.html`, 단일 파일, three.js 0.186.1을 jsDelivr에서 불러옴):
  - 원고지 바닥 위에 연필 한 자루가 지우개를 아래로 하고 선다. 글 한 편 = 종이 카드 한 장. 카드가 연필을 감고 나선(한 바퀴 11장)으로 쌓인다. 새 글이 올라올 때마다 연필이 자라고, 연필심이 가장 최근 글을 가리킨다.
  - 근거: 브루너의 '나선형 교육과정'(같은 주제로 돌아오되 매번 더 높은 곳에서). 부제 "인생은 초등학교에서 배운 것의 복습이란다"와 같은 생각.
  - 카드: 앞면은 번호·시리즈·제목·날짜·회차, 뒷면은 공책 줄. 위쪽에 시리즈 색 색인 탭(시리즈마다 탭 위치가 다름). 카드와 연필은 가는 실로 이어진다.
  - '시간의 나선' ↔ '과목별 기둥': 같은 카드가 한 장씩 뒤집히며 시리즈별 기둥으로 다시 모인다. 바닥에 시리즈 이름표.
  - 조작: 드래그로 회전, 위아래 드래그(데스크톱)나 오른쪽 '자'로 시간 이동, 카드를 누르면 가까이, 범례로 시리즈 걸러 보기, 위아래 화살표로 글 고르기.
  - 접근성: '목록으로 보기'에 같은 글이 평범한 목록으로 있다. 애니메이션 줄이기 설정이면 쌓이는 연출·자동 회전을 끈다. WebGL이 안 되면 안내 문구.
  - 조명 대신 종이 그대로(MeshBasic) 그리고, 각도에 따른 옅은 음영과 종이색 안개로만 깊이를 준다. 그림자 없음.
- 통합 화면: '생각의 구'(2안)는 THEREFORE 홈이 아니라 통합 화면의 궤도 층으로 쓴다. 공통 규칙은 [FAMILY.md](FAMILY.md).
